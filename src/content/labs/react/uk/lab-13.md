## 1. Мета роботи

Навчитися налаштовувати маршрутизацію React-застосунку за допомогою React
Router:

- описувати маршрути об'єктами, показувати сторінки в спільному макеті та
  читати параметри з адреси;
- будувати вкладені маршрути з власним макетом;
- закривати сторінки від гостей за допомогою middleware і повертати
  користувача після входу лише на адреси цього сайту;
- завантажувати код сторінки лише тоді, коли її відкривають, і перевіряти
  це у збірці та у вкладці Network.

**Очікуваний результат:** у теці `lab-13/` репозиторію `react-labs` — сайт
кінотеатру, у якому кожна сторінка має свою адресу й показується під шапкою
сайту. Кабінет і бронювання відкриваються лише після входу, а сторінка
«Вхід» повертає користувача туди, куди він ішов. Код бронювання й «Моїх
квитків» браузер завантажує окремими файлами. Обидві таблиці в
`MEASUREMENTS.md` заповнено. У теці `npm test -- --run` проходить 20 тестів
з 20, `npm run lint` — без помилок і попереджень, `format:check` і `build` —
без помилок; застосунок відкривається на Vercel, і сторінка, відкрита там за
адресою, не дає 404. За 1 додатковий бал (§4.9) виконано одне з чотирьох
додаткових завдань.

## 4. Хід виконання роботи

У стартовому проєкті — сайт кінотеатру. Усі сторінки вже написано: «Афіша»,
сторінка фільму, «Розклад», «Вхід», «Бронювання», «Кабінет» з «Профілем» і
«Моїми квитками». Але маршрут поки один: «Афіша» на адресі `/`. У цій
роботі ви налаштовуєте маршрути між сторінками, а не самі сторінки.

**Маршрутизація** (routing) означає, що застосунок показує різні сторінки
за різними адресами. **Клієнтська маршрутизація** робить це в браузері: за
кліку на посилання JavaScript змінює адресу в адресному рядку й сам показує
потрібну сторінку, не завантажуючи з сервера новий HTML. У ЛР-10 це робив
простий роутер на `location.hash`; у цій роботі — бібліотека React Router.

React Router має три режими. **Декларативний** (declarative mode) описує
маршрути JSX-елементами `<Route>` усередині компонентів. **Режим даних**
(data mode) описує маршрути масивом об'єктів поза компонентами й додає
middleware, ліниві маршрути та завантаження даних. **Фреймворковий**
(framework mode) — режим даних разом із плагіном Vite, маршрутами з файлів і
рендерингом на сервері. Ця робота пише код у режимі даних, а декларативний
режим ви бачите на прикладі в §4.3.

### 4.3. Розбір: маршрутизація на прикладі блогу

Перш ніж налаштовувати кінотеатр, розберіть готовий приклад: невеликий блог
у теці `example/`. Він показує кожен механізм React Router, потрібний у
§4.4–§4.7, один раз і в найпростішому вигляді. Кінотеатру знадобиться
більше: механізми разом і кілька рішень, яких у блозі немає. Нічого в
`example/` не змінюйте й не комітьте.

Запустіть блог у ще одному терміналі, у теці `lab-13/`:

```bash
npm run example
```

Порт 5173 зайнятий сайтом кінотеатру, тож Vite відкриє блог на наступному
вільному, наприклад http://localhost:5174. Адреса — у виводі команди.

**Маршрути.** **Маршрут** (route) пов'язує шаблон адреси з тим, що показує
застосунок. У режимі даних маршрути — масив об'єктів у
`example/routes.js`. Властивість `path` — шаблон адреси, `Component` —
компонент сторінки:

```js
export const routes = [
  {
    path: '/',
    Component: Layout,
    HydrateFallback: Loading,
    children: [
      { index: true, Component: PostsPage },
      { path: 'posts/:postId', Component: PostPage },
      {
        path: 'about',
        lazy: {
          Component: async () =>
            (await import('./pages/AboutPage.jsx')).default,
        },
      },
      { path: 'login', Component: LoginPage },
      {
        path: 'new',
        middleware: [requireAuthor],
        Component: NewPostPage,
      },
    ],
  },
  { path: '*', Component: NotFoundPage },
]
```

З цього масиву `example/App.jsx` створює роутер і передає його в
`<RouterProvider>`:

```jsx
const router = createBrowserRouter(routes)

export default function App() {
  return <RouterProvider router={router} />
}
```

`createBrowserRouter` беруть з `react-router`, а `RouterProvider` — з
`react-router/dom`, як на сторінці встановлення режиму даних. Роутер
створюється один раз, поза функцією `App`: усередині компонента він
створювався б заново на кожному рендері. `example/main.jsx`, як і в
попередніх роботах, лише рендерить `<App />` в елемент `#root`. Кінотеатр
влаштовано так само: `src/app/App.jsx` і `src/app/main.jsx`.

**Макет і вкладені маршрути.** Маршрут з `children` — **батьківський**, а
маршрути в `children` — **вкладені** (nested routes). Шлях вкладеного
маршруту продовжує шлях батьківського: `posts/:postId` усередині `/` — це
адреса `/posts/:postId`. Такий шлях без `/` на початку називають
**відносним**. **Макет** (layout) — компонент батьківського маршруту, який
показує спільне для всіх дочірніх сторінок і `<Outlet />` там, де має бути
сторінка дочірнього маршруту. Макет блогу, `example/Layout.jsx`:

```jsx
export default function Layout() {
  return (
    <div className="blog">
      <header className="blog-header">
        <Link className="blog-name" to="/">
          Нотатки з веброзробки
        </Link>
        <nav aria-label="Розділи блогу">
          <NavLink to="/about">Про блог</NavLink>
          <NavLink to="/new">Нова публікація</NavLink>
        </nav>
      </header>
      <main>
        <Outlet />
      </main>
    </div>
  )
}
```

**Індексний маршрут** (index route) — дочірній маршрут з `index: true`
замість `path`: його сторінку макет показує за адресою самого батьківського
маршруту. У блозі за адресою `/` це список публікацій.

**Посилання.** `<Link to="/">` змінює адресу без перезавантаження сторінки:
React Router перехоплює клік, змінює адресу через History API і показує
новий маршрут. Звичайне `<a href>` натомість просить у сервера сторінку
заново, і весь застосунок завантажується з початку. `<NavLink>` — той самий
`Link`, який знає, чи веде він на поточну сторінку. Тоді він додає
посиланню `aria-current="page"`: програма зчитування екрана оголошує його
поточною сторінкою, а CSS може виділити його через
`a[aria-current='page']`.

**Динамічний сегмент.** Частина шляху з двокрапкою, як `:postId`, —
**динамічний сегмент** (dynamic segment): вона збігається з будь-яким
значенням у цьому місці адреси. Компонент сторінки читає значення через
хук `useParams()`, а назва ключа — та сама, що в шляху після двокрапки.
`example/pages/PostPage.jsx`:

```jsx
export default function PostPage() {
  const { postId } = useParams()
  const post = findPost(postId)
  if (!post) return <h1>Публікацію не знайдено</h1>

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.text}</p>
      <Link to="/">Усі публікації</Link>
    </article>
  )
}
```

**Маршрут `*`.** Шлях `*` (splat) збігається з будь-якою адресою, якої не
описує жоден інший маршрут. У блозі він стоїть на верхньому рівні масиву,
поза маршрутом `/`.

**Middleware.** **Middleware** маршруту — функція, яку React Router викликає
перед тим, як показати маршрут, спершу для батьківського маршруту, потім для
дочірнього. Вона може зупинити перехід, кинувши `redirect(адреса)`: тоді
React Router переходить на цю адресу, а сторінки маршруту не показує й не
рендерить. Маршрут `new` має `middleware: [requireAuthor]`,
`example/middleware.js`:

```js
export function requireAuthor() {
  if (!getUser()) {
    throw redirect('/login')
  }
}
```

`getUser()` читає несправжню сесію блогу з `sessionStorage`. Сторінка «Вхід»
після кліку на кнопку записує автора й переходить на головну через
`useNavigate()` — хук, який повертає функцію переходу на іншу адресу з коду:

```jsx
const navigate = useNavigate()

function handleClick() {
  signIn()
  navigate('/')
}
```

**Ліниве завантаження.** **Ліниве завантаження** (lazy loading) означає, що
браузер завантажує код сторінки лише тоді, коли сторінку відкривають. Маршрут
`about` замість `Component` має `lazy`: об'єкт, у якому `Component` —
асинхронна функція. `import()` з дужками — динамічний імпорт: Vite кладе
`AboutPage.jsx` в окремий файл збірки, і браузер завантажує його лише тоді,
коли React Router викликає цю функцію, тобто коли користувач відкриває «Про
блог». Сторінка «Route Object» показує ще одну форму `lazy` — функцію, яка
повертає об'єкт з `Component`; у цій роботі підходить будь-яка.

**`HydrateFallback`.** Коли сайт відкривають одразу за адресою лінивої
сторінки, показати нічого: код сторінки ще не завантажено. Тоді React Router
показує компонент з `HydrateFallback` кореневого маршруту, у блозі —
«Завантаження…». Перший рендер застосунку React Router називає
«hydration» навіть тоді, коли сервер нічого не рендерив. Без
`HydrateFallback` він пише в консоль попередження «No `HydrateFallback`
element provided to render during initial hydration».

**Той самий блог у декларативному режимі.** У старіших посібниках і
відповідях, написаних до появи режиму даних (React Router 6.4), маршрути

`<BrowserRouter>`, а маршрути — у `example/DeclarativeApp.jsx`:

```jsx
const AboutPage = lazy(() => import('./pages/AboutPage.jsx'))

function RequireAuthor() {
  const user = useUser()
  if (!user) return <Navigate to="/login" replace />
  return <Outlet />
}

export default function DeclarativeApp() {
  return (
    <Suspense fallback={<p className="loading">Завантаження…</p>}>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<PostsPage />} />
          <Route path="posts/:postId" element={<PostPage />} />
          <Route path="about" element={<AboutPage />} />
          <Route path="login" element={<LoginPage />} />
          <Route element={<RequireAuthor />}>
            <Route path="new" element={<NewPostPage />} />
          </Route>
        </Route>
        <Route path="*" element={<NotFoundPage />} />
      </Routes>
    </Suspense>
  )
}
```

Перевірку тут робить компонент `RequireAuthor`, як `ProtectedRoute` у
статті Robin Wieruch: під час рендеру він повертає `<Navigate>`, який
переходить на `/login`, або `<Outlet />`. Код «Про блог» завантажує
`React.lazy`, а поки він завантажується, `<Suspense>` показує свій
`fallback`. Щоб запустити цю версію, у `example/index.html` замініть
`/main.jsx` на `/main-declarative.jsx`, а потім поверніть як було.

|                                       | Режим даних                                              | Декларативний режим                                                    |
| ------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------- |
| Де описано маршрути                   | масив об'єктів поза React                                | JSX усередині компонента                                               |
| Коли працює перевірка                 | middleware, до того як маршрут рендериться               | `RequireAuthor`, під час рендеру маршруту                              |
| Як завантажується код сторінки        | `lazy` маршруту, під час переходу                        | `React.lazy`, коли елемент рендериться вперше, з `fallback` `Suspense` |
| Що видно, поки код завантажується     | попередня сторінка; стан переходу знає `useNavigation()` | `fallback` `<Suspense>`                                                |
| Middleware, `useNavigation`, `handle` | є                                                        | немає (таблиця API на «Picking a Mode»)                                |

У декларативному режимі вам ще трапляться імпорти з `react-router-dom`.
Версія 8 цього пакета більше не публікує: ті самі компоненти й хуки беруть з
`react-router`.

### 4.6. Захищені маршрути

Після цього завдання бронювання й усі сторінки кабінету відкриваються лише
користувачу, який увійшов. Гість потрапляє на «Вхід», а адреса зберігає в
параметрі `redirectTo`, куди він ішов, разом із query. Після входу
користувач переходить туди, але лише на адресу цього сайту, і «Назад» веде
на сторінку, з якої він прийшов. Користувач, який уже ввійшов, на «Вхід» не
потрапляє. «Вийти» веде на «Афішу». Тести завдання —
`npm test -- tests/protected`, 7 тестів.

Перевірки — middleware, як `requireAuthor` у блозі. Middleware працює до
того, як будь-яка частина захищеної сторінки рендериться; тести це
перевіряють. Але перевірка в браузері вирішує лише, що побачить
відвідувач: дані сторінки сервер мусить перевіряти сам на кожному запиті.

**Чому `safeRedirect`.** Значення `redirectTo` береться з адреси, а адресу
може написати будь-хто. Посилання `/login?redirectTo=//інший-сайт` після
справжнього входу відправило б користувача на чужий сайт. Це **відкрите
перенаправлення** (open redirect), описане в шпаргалці OWASP. Готова
функція `safeRedirect(to)` з `src/shared/utils/safeRedirect.js` повертає
`to`, лише якщо це шлях на цьому сайті, а інакше — `/account`.

1. **`requireUser`.** У `src/app/authMiddleware.js` замініть тіло
   заготовки `requireUser`. Функція отримує об'єкт із полем `request`.
   Якщо `getUser()` повертає `null`, вона бере з `new URL(request.url)`
   шлях (`pathname`) і query (`search`) адреси, яку відкривав гість, і
   кидає `redirect` на `/login?redirectTo=` з цим шляхом. Значення
   закодуйте через `URLSearchParams`, щоб `/` і `?` у ньому не зламали
   адресу. `redirect` імпортуйте з `react-router`, `getUser` — з
   `../shared/auth/session.js`.
2. **Захищені маршрути.** У `routes.js` додайте в `children` маршруту `/`
   маршрут без `path` з `middleware: [requireUser]` і перенесіть у його
   `children` маршрути `booking/:sessionId` і `account`. Маршрут без `path`
   нічого не додає до адреси: він лише запускає свою middleware перед
   кожним дочірнім маршрутом, тож одна перевірка закриває і бронювання, і
   весь кабінет. Додайте кореневому маршруту `/` властивість
   `HydrateFallback` з готовим компонентом із `src/shared/components/`:
   middleware працює ще до першого рендеру, і поки вона працює, React
   Router показує цей компонент, а без нього пише попередження. Крок
   завершено, коли проходить 1 тест з 7.
3. **Повернення після входу.** У `src/routes/login/LoginPage.jsx` прочитайте
   `redirectTo` з адреси через `useSearchParams()`, пропустіть його через
   `safeRedirect` і на місці коментаря перейдіть туди функцією з
   `useNavigate()`, з опцією `replace: true`. `replace` замінює «Вхід» в
   історії браузера новою сторінкою, тож «Назад» веде туди, звідки гість
   прийшов, а не на «Вхід». Крок завершено, коли проходять 4 тести з 7.
4. **`guestOnly`.** Напишіть `guestOnly`: якщо `getUser()` повертає
   користувача, вона бере `redirectTo` з `request.url` і кидає `redirect` на
   адресу, яку повертає `safeRedirect(redirectTo)`. Додайте маршруту
   `login` `middleware: [guestOnly]`. Крок завершено, коли проходять 6
   тестів з 7.
5. **«Вийти».** У `RootLayout` після `signOut()` перейдіть на `/` функцією з
   `useNavigate()`. Без переходу захищена сторінка лишається на екрані:
   middleware працює лише тоді, коли відбувається перехід. Крок завершено,
   коли проходять 7 тестів з 7, а `npm test -- --run` показує 18 з 20.

**Перевірка в браузері.** Як гість відкрийте фільм, клацніть сеанс,
увійдіть і натисніть «Назад»: ви на сторінці фільму. Коли ви вже ввійшли,
відкрийте `/login?redirectTo=//example.com`: ви маєте опинитися в кабінеті.

**Довідка:** [Middleware](https://reactrouter.com/how-to/middleware)
(розділ «Authentication»), [Route Object: `middleware`](https://reactrouter.com/start/data/route-object#middleware),
[`useSearchParams`](https://reactrouter.com/api/hooks/useSearchParams),

### 4.7. Ліниві маршрути

Тепер код бронювання й «Моїх квитків» завантажуватиметься лише тоді, коли
відкривається одна з цих сторінок, як «Про блог» у блозі. Ефект ви
вимірюєте у збірці та в браузері й записуєте в `MEASUREMENTS.md`. Тести
завдання — `npm test -- tests/lazy`.

1. **Збірка до змін.** Виконайте `npm run build` і запишіть кожен
   `.js`-файл з `dist/assets/` у рядок «після §4.6» першої таблиці,
   «Файли збірки».
2. **Ліниві сторінки.** У `routes.js` у маршруті `booking/:sessionId`
   замініть `Component` на `lazy`, як у маршруті `about` блогу: об'єкт, у
   якому `Component` — асинхронна функція, що імпортує
   `../routes/booking/BookingPage.jsx` через `import()` і повертає його
   `default`. Так само зробіть маршрут `tickets` з `TicketsPage`. Приберіть
   обидва імпорти з початку файлу: поки сторінку імпортовано там, її код
   потрапляє в основний файл збірки. Крок завершено, коли
   `npm test -- --run` показує 20 з 20.
3. **Збірка після змін.** Виконайте `npm run build` ще раз і запишіть файли
   в рядки «після §4.7». Якщо дві ліниві сторінки імпортують той самий
   модуль, Vite кладе його в ще один окремий файл, названий за цим модулем.
4. **Що завантажує браузер.** Зупиніть dev-сервер, виконайте
   `npm run preview` і відкрийте адресу, яку покаже сервер. В інструментах
   розробника відкрийте вкладку **Network**, фільтр **JS**, і позначте
   **Disable cache**. Для кожного рядка другої таблиці відкрийте адресу в
   адресному рядку й запишіть, які з двох файлів сторінок завантажено.
   Щоб відкрити адресу гостем, закрийте вкладку з сайтом і відкрийте нову;
   щоб глядачем — увійдіть і відкрийте адресу знову. Таблиця відповідає на
   питання, чи не дає захищений маршрут гостю завантажити код захищеної
   сторінки; §6 питає, чому так.

**Коміт:** `perf: load the booking and tickets pages lazily`, разом із
заповненим `MEASUREMENTS.md`.
**Довідка:** [Route Object: `lazy`](https://reactrouter.com/start/data/route-object#lazy).

## 6. Усний захист

Формат здачі передбачає усну співбесіду за результатами роботи. Питання
нижче — типові питання співбесіди frontend-розробника з тем цієї роботи.
Відповідайте на прикладах власного коду. Викладач може попросити показати
відповідь у коді, тестах чи браузері, додати маршрут чи виправити помилку
наживо, без AI. Питання групи «Додаткові завдання» глибше ставлять тим, хто
виконав відповідне завдання.

**Питання для підготовки:**

_Клієнтська маршрутизація_

- Що робить клієнтський роутер замість браузера? Що робить `<Link>`, чого не
  робить `<a href>`?
- Чому Vercel потрібен `vercel.json`, а dev-серверу Vite — ні?
- Порівняйте роутер на `location.hash` з ЛР-10 і History API, яким
  користується React Router.

_Маршрути й макети_

- Що таке макет і `<Outlet />`? Порівняйте індексний маршрут і дочірній
  маршрут зі шляхом.
- Чому шляхи дочірніх маршрутів кабінету відносні? Що буде з абсолютним
  шляхом?
- Звідки береться назва ключа, який повертає `useParams()`?
- Як працює маршрут `*`? Чому невідомий фільм показує власне повідомлення, а
  не сторінку маршруту `*`?
- Що дає `aria-current="page"`? Чому «Профілю» потрібен `end`, а «Кабінету»
  й «Афіші» — ні?

_Режими React Router_

- Порівняйте три режими React Router. Що додає режим даних?
- Порівняйте режими за таблицею з §4.3: коли кожен перевіряє користувача,
  як завантажує код сторінки і що показує тим часом.
- Де кожен режим може зберігати адресу, на яку повернути після входу: query
  в кінотеатрі проти `location.state` у статті Robin Wieruch. Чому
  кінотеатр бере query?
- Чому у версії 8 немає `react-router-dom`? Що змінити в посібнику,
  написаному для нього?

_Блог і кінотеатр_

- Чого кінотеатру знадобилося, чого не було в блозі, і де ви знайшли, як
  це зробити?
- Чому сторінка 404 блогу без шапки, а кінотеатру — з шапкою?
- Чим перевірка кінотеатру відрізняється від перевірки блогу?

_Захищені маршрути_

- Що таке middleware маршруту? У якому порядку React Router викликає
  middleware батьківського й дочірнього маршрутів?
- На яких маршрутах стоїть ваша `requireUser` і чому там? Що змінилося б,
  якби вона стояла на кожному захищеному маршруті окремо?
- Чому перевірка — middleware, а не компонент, як `RequireAuthor` у
  декларативному блозі? Що перевіряють тести, чого не було б видно на
  сторінці?
- Навіщо `replace` після входу? Що робить «Назад» без нього до появи
  `guestOnly` і після?
- Навіщо `safeRedirect` і на сторінці «Вхід», і в `guestOnly`? Що дало б
  відкрите перенаправлення тому, хто надіслав посилання?
- Чому несправжня сесія — модуль зі сховищем на `useSyncExternalStore`, а не
  контекст, як у ЛР-12? Хто читає сесію поза компонентами?
- Чому «Вийти» має кудись перейти? Що бачив би користувач, якби «Вийти»
  лише виходило?
- Що мав би перевіряти сервер, чого не може перевірити код у браузері?

_Ліниве завантаження_

- Що `lazy` змінив у збірці? Поясніть за першою таблицею.
- Чи завантажує браузер гостя код захищеної сторінки? Поясніть за другою
  таблицею, чому так і чому це не робить сайт менш захищеним.
- Коли React Router показує `HydrateFallback`?
- Порівняйте `lazy` маршруту з `React.lazy`. Що може завантажити ліниво
  `React.lazy`, чого не може `lazy` маршруту?

_Тести_

- Як тест відкриває сайт за адресою? Чому тестам не потрібен адресний рядок
  браузера?
- Навіщо допоміжна функція тестів копіює маршрути для кожного роутера?
- Як тест бачить, що модуль сторінки не завантажено? Як — що компонент не
  рендерився?
- Чому тести додаткових завдань — окремий набір Vitest?

_Додаткові завдання_

- Навіщо переводити фокус і змінювати назву вкладки після переходу? Чому не
  під час першого відкриття сайту?
- Порівняйте сторінку 403 і перенаправлення на «Вхід»: коли що доречне?
  Де React Router шукає `ErrorBoundary` для помилки з middleware?
- Чому в режимі даних попередня сторінка лишається на місці, поки
  завантажується наступна?
- Порівняйте вхід, що починається з посилання на публічній сторінці, і вхід,
  що починається з перевірки. Що middleware отримує, крім `request`? Чому
  фільм, недоступний онлайн, — помилка, а не перенаправлення?
