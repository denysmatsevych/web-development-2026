## 1. Загальна ідея

**ShowFinder** — пошук серіалів у [TVmaze](https://www.tvmaze.com) через його
публічний [API](https://www.tvmaze.com/api). Користувач вводить назву й
натискає «Знайти», бачить знайдені серіали й відкриває сторінку одного з них.
Стан живе лише в пам'яті: після перезавантаження сторінки застосунок починає
спочатку.

Застосунок написано на JavaScript, і ви переводите його на TypeScript. Спершу
власноруч — те, на чому тримаються всі інші модулі: типи відповідей API,
запити й стани сторінки (T1–T3). Потім решту модулів — поведінку, показ даних,
пошук елементів сторінки й точку входу — переводить AI-агент, а ви перевіряєте
його міграцію й виправляєте її (T4).

> Самоперевірка `npm run check` — це ця специфікація у вигляді коду: назва
> кожного тесту й коментар біля кожної перевірки типів починаються з номера
> правила з §4 (або «§5» — для обмежень). Якщо перевірка й текст нижче
> здаються вам суперечливими, повідомте викладача.

## 2. Структура проєкту

**Завантажити:** [showfinder-ts-starter.zip](/labs/showfinder-ts-starter.zip).
Розпакуйте архів в окремий репозиторій або в теку `lab-12/` спільного
репозиторію з лабораторними.

```text
showfinder-ts-starter/
├── package.json, tsconfig.json  скрипти й налаштування компілятора
├── index.html, styles.css       сторінка й стилі
├── src/
│   ├── types.ts     T1 · типи відповідей API
│   ├── api.ts       T2 · запити
│   ├── state.ts     T3 · стани й тексти
│   ├── app.js       T4 · поведінка: пошук і сторінка серіалу
│   ├── view.js      T4 · показ даних
│   ├── dom.js       T4 · елементи сторінки
│   └── main.js      T4 · точка входу
├── check/           самоперевірка: перевірки типів, тести, записані відповіді TVmaze
└── README.md        запуск, самоперевірка, редактор
```

Потрібен Node.js 22.18 або новіший.

| Команда | Що робить |
| --- | --- |
| `npm install` | один раз: встановлює TypeScript |
| `npm run watch` | компілює `src/` у `dist/` і стежить за змінами; сторінку відкривайте через Live Preview |
| `npm run check` | перевірка типів і тести; наприкінці — «Типи: … · Тести: пройдено N з M» |
| `npm run typecheck` | лише перевірка типів |
| `npm test` | лише тести |

Поки в `src/` є файли `.js`, `tsc` теж кладе їх у `dist/`, але типів у них не
перевіряє (`allowJs` у `tsconfig.json`). Так проєкт працює посеред міграції:
модулі `.ts` і `.js` імпортують один одного.

## 3. API, дані й стани

### 3.1. TVmaze API

| Що | Запит | Відповідь |
| --- | --- | --- |
| Пошук | `GET https://api.tvmaze.com/search/shows?q=<запит>` | `200` і масив до 10 елементів `{ score, show }`; немає збігів — `200 []` |
| Серіал | `GET https://api.tvmaze.com/shows/<id>` | `200` і об'єкт серіалу; немає такого id — `404` |

Ключ не потрібен. TVmaze гарантує щонайменше 20 запитів за 10 секунд з однієї
IP-адреси, а понад це відповідає `429`.

### 3.2. Серіал

Застосунок використовує лише ці поля серіалу. Інших полів відповіді тип `Show`
не описує.

| Поле | Що це | Приклад (Girls, id 139) |
| --- | --- | --- |
| `id` | ідентифікатор | `139` |
| `url` | сторінка серіалу на сайті TVmaze | `"https://www.tvmaze.com/shows/139/girls"` |
| `name` | назва | `"Girls"` |
| `genres` | жанри; буває порожнім масивом | `["Drama", "Romance"]` |
| `premiered` | дата прем'єри або `null` | `"2012-04-15"` |
| `rating` | завжди об'єкт; його `average` — число або `null` | `{ "average": 6.4 }` |
| `image` | постер: об'єкт з адресами `medium` і `original` або `null` | `{ "medium": "https://…", "original": "https://…" }` |
| `summary` | опис — рядок з HTML — або `null` | `"<p>This Emmy winning series…</p>"` |

### 3.3. Сторінка й модулі JavaScript

| Елемент | Що це |
| --- | --- |
| `form#search` | поле `#search-query` і кнопка «Знайти» |
| `#status` | рядок статусу, `role="status"` |
| `#content` | картки результатів або сторінка серіалу |

Модулі нижче написано на JavaScript. До T4 їх не змінюйте: коли T1–T3
виконано, застосунок працює з ними в браузері.

| Модуль | Експорт | Що робить |
| --- | --- | --- |
| `src/dom.js` | `pageElements()` | повертає `{ form, input, status, content }` — елементи вище |
| `src/view.js` | `renderResults(container, shows)` | картки серіалів; кожна картка — кнопка `button[data-id]` з id серіалу |
| `src/view.js` | `renderShow(container, show)` | сторінка серіалу; її заголовок отримує фокус |
| `src/view.js` | `renderStatus(status, text, state)` | текст рядка статусу; `state` — поле `status` стану, від нього залежить оформлення |
| `src/view.js` | `showMeta(show)` | рядок під назвою серіалу: рік і оцінка (§3.4) |
| `src/app.js` | `loadSearch(query, setState)`, `loadShow(id, setState)` | пошук і сторінка серіалу: кожну зміну стану передають у `setState` |
| `src/app.js` | `start()` | підключає форму й картки до сторінки; її викликає `main.js` |

### 3.4. Стани й тексти

Сторінка завжди в одному з шести станів:

```ts
type ViewState =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'results'; query: string; shows: Show[] }
  | { status: 'empty'; query: string }
  | { status: 'show'; show: Show }
  | { status: 'error'; message: string };
```

| Стан | Рядок статусу | `#content` |
| --- | --- | --- |
| `idle` | `Введіть назву серіалу.` | порожньо |
| `loading` | `Завантаження…` | порожньо |
| `results` | `Знайдено серіалів: 10` — кількість у `shows` | картки |
| `empty` | `Нічого не знайдено за запитом «qqqzzz»` — з `query` | порожньо |
| `show` | `Серіал: Girls` — назва серіалу | сторінка серіалу |
| `error` | `message` без змін | порожньо |

Тексти помилок для користувача:

| Помилка | Текст |
| --- | --- |
| `HttpError` зі статусом 404 | `Не знайдено (HTTP 404).` |
| `HttpError` 429 | `Забагато запитів (HTTP 429). Спробуйте за кілька секунд.` |
| `HttpError` 500–599 | `Сервер TVmaze недоступний (HTTP 503). Спробуйте пізніше.` — зі справжнім статусом |
| будь-який інший `HttpError` | `Помилка запиту (HTTP 400).` — зі справжнім статусом |
| `TypeError` — так `fetch` повідомляє про збій мережі | `Мережа недоступна. Перевірте підключення.` |
| будь-що інше | `Щось пішло не так. Спробуйте ще раз.` |

Рядок під назвою серіалу — на картці й на сторінці серіалу (`showMeta`):

| Серіал | Текст |
| --- | --- |
| `premiered: "2012-04-15"`, `rating.average: 6.4` | `2012 · оцінка 6.4` |
| `premiered: "2018-06-15"`, `rating.average: null` | `2018 · оцінка —` |
| `premiered: null`, `rating.average: null` | `рік невідомий · оцінка —` |

Тести порівнюють тексти точно, лише «...» зараховують як «…».

## 4. Завдання

Виконуйте завдання по черзі: кожне спирається на попередні. T1–T3 пишете
власноруч, AI-агент може лише пояснювати. У T4 модулі переводить AI-агент, а
ви перевіряєте міграцію й виправляєте її (лабораторна робота, §5.2).

Правила пронумеровано: T2.4 — четверте правило завдання T2. Кожне правило
перевіряє `npm run check`:

- **тест**, назва якого починається з номера правила;
- або **перевірка типів** у `check/types.check.ts`: помилка компілятора
  вказує на рядок, а номер правила стоїть у коментарі над ним або в кінці
  рядка. «Unused '@ts-expect-error' directive» означає, що ваш тип пропускає
  значення, яке мав би заборонити.

### T1. Типи відповідей API

**Що має вийти.** У `src/types.ts` — експортовані інтерфейси `Show` і
`SearchResult`, що точно описують відповіді TVmaze (§3.1–3.2): `null` там, де
він буває, і ніде більше.

**Як.** Відкрийте `https://api.tvmaze.com/search/shows?q=girls` у браузері
(експеримент Е1) і `check/fixtures/search.json`. Серіали, у яких поля
бувають `null`, є, наприклад, у пошуку `kitchen`.

**Правила:**

1. `id` — `number`; `name` і `url` — `string`; `genres` — масив рядків.
2. `image`, `summary`, `premiered` і `rating.average` можуть бути `null`, а
   `name` — ні. `image`, коли не `null`, — об'єкт з рядками `medium` і
   `original`; `rating` — завжди об'єкт.
3. `SearchResult` — `{ score: number; show: Show }`.
4. Записані відповіді TVmaze з `check/fixtures/` підходять під ваші типи без
   змін.

**Перевірка:** `npm run typecheck`, блок T1 у `check/types.check.ts`.

### T2. Запити

**Що має вийти.** У `src/api.ts` — типізовані функції запитів до TVmaze. Дані
з мережі мають тип `unknown`: код вважає їх серіалами лише після перевірки
type guard.

**Правила:**

1. `class HttpError extends Error` з полем `readonly status: number`:
   `new HttpError(404)` — помилка зі `status` 404 і статусом у повідомленні.
2. `getJson(url: string): Promise<unknown>` надсилає GET-запит через `fetch`.
   Якщо статус поза 200–299 — відхиляє проміс з `HttpError`, інакше повертає
   розібране тіло JSON. Помилку самого `fetch` (збій мережі) не змінює.
3. `isShow(value: unknown): value is Show` повертає `true`, якщо `value` —
   об'єкт з числовим `id`, рядковим `name` і масивом `genres`, інакше
   `false`. `isSearchResult(value: unknown): value is SearchResult` — так само
   для об'єкта з числовим `score` і полем `show`, на якому `isShow` дає
   `true`. `value` звужуйте перевірками — `typeof`, `in`, `Array.isArray`, — а
   не твердженням `as` (§5).
4. `searchShows(query: string): Promise<Show[]>` запитує
   `GET https://api.tvmaze.com/search/shows?q=<запит>` з закодованим запитом:
   «law & order» доходить до API повністю. Повертає серіали, а не елементи
   `{ score, show }`, у порядку відповіді; немає збігів — `[]`.
5. `getShow(id: number): Promise<Show>` запитує
   `GET https://api.tvmaze.com/shows/<id>` і повертає серіал.
6. На статус 404, 429, 500 чи 503 обидві функції відхиляють проміс з
   `HttpError` цього статусу.
7. Якщо тіло відповіді не тієї форми (`isSearchResult` чи `isShow` дає
   `false`), обидві функції відхиляють проміс з
   `new Error('Неочікувана відповідь API')`.

**Перевірка:** тести T2 (`check/2-api.test.js`) і блок T2 у
`check/types.check.ts`.

### T3. Стани й тексти

**Що має вийти.** У `src/state.ts` — тип стану сторінки й дві функції, що
перетворюють стан і помилку на текст для користувача (§3.4).

**Правила:**

1. `export type ViewState` — об'єднання шести станів з §3.4, кожен лише зі
   своїми полями. Поле `status` розрізняє стани.
2. `errorMessage(err: unknown): string` повертає текст помилки з §3.4.
   `HttpError` розпізнає лише через `instanceof`: звичайний об'єкт
   `{ status: 404 }` — це «будь-що інше».
3. `messageFor(state: ViewState): string` повертає текст рядка статусу з
   §3.4. Усередині — `switch (state.status)` з гілкою `default`, у якій стан
   присвоєно змінній типу `never`: якщо колись додати сьомий стан і не
   обробити його, компілятор покаже помилку. Під час виконання ця гілка не
   настає, тож у ній можна просто кинути помилку.

**Перевірка:** тести T3 (`check/3-state.test.js`) і блок T3 у
`check/types.check.ts`. Після T3 застосунок уже працює в браузері, а
`npm run check` показує «Типи: без помилок · Тести: пройдено 39 з 48»: решта
тестів — T4.

### T4. Міграція: AI-агент → перевірка → виправлення

**Що має вийти.** `src/app.js`, `src/view.js`, `src/dom.js` і `src/main.js`
стали файлами `.ts` з типами. `npm run check` не показує жодної помилки, а
застосунок працює в браузері зі справжнім TVmaze (§6).

**Що тут перевіряти.** У JavaScript-модулях є дефекти, тому частина тестів T4
падає ще до міграції. Щойно файли стануть `.ts`, частину дефектів покаже
компілятор у режимі strict, а решту — лише тести. Агент може виправити дефект,
а може лише прибрати помилку компілятора: `as`, `!`, `any`, `declare`,
`@ts-ignore` чи вимкнена перевірка в `tsconfig.json` прибирають помилку, але не
дефект. Тому
міграцію перевіряєте ви — за правилами нижче й обмеженнями §5.

**Запит для AI-агента** (вставте слово в слово):

> Переведи на TypeScript файли src/app.js, src/view.js, src/dom.js і
> src/main.js: перейменуй кожен на .ts і додай типи. Використай типи з
> src/types.ts і src/state.ts і функції з src/api.ts. Поведінку застосунку не
> змінюй. Теку check/ не відкривай і не змінюй; src/types.ts, src/api.ts,
> src/state.ts, index.html і tsconfig.json не змінюй.

**Правила:**

1. У `src/` лише файли `.ts`: `app.ts`, `view.ts`, `dom.ts` і `main.ts`
   замінили свої `.js`-версії. Модулі імпортують один одного з розширенням
   `.ts`: шлях `./view.js` браузер ще знайде в `dist/`, а тести в Node — ні.
2. `tsconfig.json` і `check/tsconfig.json` такі самі, як у starter-проєкті:
   помилку типів виправляють у коді, а не вимикаючи `strict` чи іншу
   перевірку.
3. `loadSearch(query: string, setState: (state: ViewState) => void):
   Promise<void>` шукає за запитом без пробілів на краях. Порожній запит —
   лише `setState({ status: 'idle' })`, без запиту до API. Інакше — спершу
   стан `loading`, ще до запиту, потім один стан: `results` з `query` і
   серіалами або `empty` з `query`, якщо нічого не знайдено.
4. Будь-яка помилка в `loadSearch` — стан `error` з
   `message: errorMessage(err)` (T3.2). Проміс `loadSearch` ніколи не
   відхиляється: у Console немає `Uncaught (in promise)`.
5. `loadShow(id: number, setState: (state: ViewState) => void):
   Promise<void>` — стан `loading`, потім `show` або `error`, як у правилі 4.
   Серіал отримує лише через `getShow` (T2.5): у `app`, `view`, `dom` і
   `main` немає ні `fetch`, ні `.json()`. Тоді 404 чи тіло не тієї форми
   стають помилкою, а не «серіалом».
6. `showMeta(show: Show): string` у `view.ts` повертає рядок під назвою
   серіалу з §3.4, зокрема для серіалів без дати прем'єри й без оцінки.
7. `start(): void` бере елементи сторінки через `pageElements()` лише
   всередині себе: тести виконуються в Node, де сторінки немає. Надсилання
   форми без перезавантаження сторінки викликає `loadSearch` зі значенням
   поля. Клік по картці `button[data-id]` викликає `loadShow` з її id як
   числом (делегування подій на `#content`). Кожен стан показується за §3.4.
   Після запуску — стан `idle`. Елементи сторінки й `event.target` звужуйте
   через `instanceof`, а не твердженням типу (§5).

**Перевірка:** тести T4 (`check/4-app.test.js`), блок T4 у
`check/types.check.ts` і тести «§5». Якщо всі тести поведінки T4 падають з
`ReferenceError: document is not defined`, порушено правило 7. Решту правила 7
перевіряєте в браузері, чек-листом §6.

## 5. Обмеження

- Власноруч ви змінюєте `src/types.ts`, `src/api.ts` і `src/state.ts`. У T4
  чотири файли `src/*.js` стають файлами `.ts`. `check/`, `index.html`,
  `styles.css`, `package.json` і `tsconfig.json` лишаються такими, як у
  starter-проєкті.
- У `src/` немає `any`.
- У `src/` немає тверджень типу (type assertions): `as` (дозволено лише
  `as const`), `!` після виразу (`value!`), `<Show>value`, а також
  `querySelector<…>()` і `closest<…>()` — те саме твердження, записане як
  аргумент типу. Тип звужують перевіркою: `typeof`, `instanceof`, `in`,
  `Array.isArray`, порівнянням з `null` чи type guard.
- У `src/` немає коментарів `@ts-ignore`, `@ts-nocheck` і `@ts-expect-error`:
  помилку типів виправляють у типі чи коді, а не вимикають.
- У `src/` немає `declare` і файлів `.d.ts`. Оголошення на кшталт
  `declare global { interface EventTarget { … } }` доповнює типи DOM без
  жодної перевірки — це те саме твердження типу, лише для всього проєкту.
- Типи імпортують через `import type` (або `type` в імпорті:
  `import { errorMessage, type ViewState }`).
- Лише `fetch` і лише `https://api.tvmaze.com`: без бібліотек і фреймворків.
- Без `alert()`, `confirm()` і `prompt()`.
- T1–T3 і виправлення T4 пишете ви. AI-агент виконує лише міграцію T4 і може
  пояснювати (лабораторна робота, §5.2).

Обмеження перевіряють тести «§5». Вони читають як текст код усіх файлів
`src/`, разом із підтеками, і не рахують коментарів і вмісту рядків.

## 6. Чек-лист у браузері

`npm run check` не бачить ні справжнього TVmaze, ні браузера: їх перевіряєте
ви. Поки працює `npm run watch`, відкрийте `index.html` через Live Preview у
Chrome або Edge і тримайте відкритою Console. Пройдіть чек-лист на фінальній
версії й додайте до звіту знімок екрана для кожного пункту.

1. **B1 · Пошук.** Знайдіть «law & order»: на сторінці — картки й
   «Знайдено серіалів: N», у Network — запит до `/search/shows` зі статусом
   200.
2. **B2 · Порожні поля.** Знайдіть «kitchen». Картка Harlem's Kitchen — без
   постера (сірий прямокутник) і з рядком «рік невідомий · оцінка —». У
   Console немає помилок.
3. **B3 · Сторінка серіалу.** Клік по картці: сторінка серіалу, у статусі —
   «Серіал: <назва>». Фокус — на заголовку серіалу: Console показує його на
   `document.activeElement`.
4. **B4 · Немає мережі.** DevTools → Network → Throttling — **Offline**.
   Пошук серіалу, якого ви ще не шукали, показує «Мережа недоступна.
   Перевірте підключення.», у Console немає `Uncaught`. (Відповідь на
   повторний запит браузер може взяти з кешу: TVmaze дозволяє зберігати її
   годину.) Поверніть **No throttling**: наступний пошук знаходить серіали.
