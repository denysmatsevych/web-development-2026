## 1. Загальна ідея

**ShowFinder** — пошук серіалів у [TVmaze](https://www.tvmaze.com) через його
публічний [API](https://www.tvmaze.com/api), цього разу на TypeScript.
Користувач вводить назву й натискає «Знайти», бачить знайдені серіали й
відкриває сторінку одного з них. Стан живе лише в пам'яті: після
перезавантаження сторінки застосунок починає спочатку.

Розмітка, стилі, показ даних (`src/view.ts`) і пошук елементів сторінки
(`src/dom.ts`) готові. Ваша частина — чотири файли, по одному на завдання §4:
типи відповідей API, запити, стани й тексти пишете власноруч, а поведінку
застосунку спершу пише AI-агент, і ви її перевіряєте й виправляєте.

> Самоперевірка `npm run check` — це ця специфікація у вигляді коду: назва
> кожного тесту й коментар біля кожної перевірки типів починаються з номера
> правила з §4. Якщо перевірка й текст нижче здаються вам суперечливими,
> повідомте викладача.

## 3. API, дані й стани

### 3.1. TVmaze API

| Що | Запит | Відповідь |
| --- | --- | --- |
| Пошук | `GET https://api.tvmaze.com/search/shows?q=<запит>` | `200` і масив до 10 елементів `{ score, show }`; немає збігів — `200 []` |
| Серіал | `GET https://api.tvmaze.com/shows/<id>` | `200` і об'єкт серіалу; немає такого id — `404` |

Ключ не потрібен. TVmaze гарантує щонайменше 20 запитів за 10 секунд з однієї
IP-адреси, а понад це відповідає `429`.

### 3.2. Серіал

Застосунок використовує лише ці поля серіалу. Інших полів відповіді тип `Show`
не описує.

| Поле | Що це | Приклад (Girls, id 139) |
| --- | --- | --- |
| `id` | ідентифікатор | `139` |
| `url` | сторінка серіалу на сайті TVmaze | `"https://www.tvmaze.com/shows/139/girls"` |
| `name` | назва | `"Girls"` |
| `genres` | жанри; буває порожнім масивом | `["Drama", "Romance"]` |
| `premiered` | дата прем'єри або `null` | `"2012-04-15"` |
| `rating` | завжди об'єкт; його `average` — число або `null` | `{ "average": 6.4 }` |
| `image` | постер: об'єкт з адресами `medium` і `original` або `null` | `{ "medium": "https://…", "original": "https://…" }` |
| `summary` | опис — рядок з HTML — або `null` | `"<p>This Emmy winning series…</p>"` |

### 3.3. Сторінка й надані модулі

| Елемент | Що це |
| --- | --- |
| `form#search` | поле `#search-query` і кнопка «Знайти» |
| `#status` | рядок статусу, `role="status"` |
| `#content` | картки результатів або сторінка серіалу |

| Модуль | Експорт | Що робить |
| --- | --- | --- |
| `src/dom.ts` | `pageElements()` | повертає `{ form, input, status, content }` — елементи вище, уже потрібного типу |
| `src/view.ts` | `renderResults(container, shows)` | картки серіалів; кожна картка — кнопка `button[data-id]` з id серіалу |
| `src/view.ts` | `renderShow(container, show)` | сторінка серіалу; її заголовок отримує фокус |
| `src/view.ts` | `renderStatus(status, text, state)` | текст рядка статусу; `state` — поле `status` стану, від нього залежить оформлення |

### 3.4. Стани й тексти

Сторінка завжди в одному з шести станів:

```ts
type ViewState =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'results'; query: string; shows: Show[] }
  | { status: 'empty'; query: string }
  | { status: 'show'; show: Show }
  | { status: 'error'; message: string };
```

| Стан | Рядок статусу | `#content` |
| --- | --- | --- |
| `idle` | `Введіть назву серіалу.` | порожньо |
| `loading` | `Завантаження…` | порожньо |
| `results` | `Знайдено серіалів: 10` — кількість у `shows` | картки |
| `empty` | `Нічого не знайдено за запитом «qqqzzz»` — з `query` | порожньо |
| `show` | `Серіал: Girls` — назва серіалу | сторінка серіалу |
| `error` | `message` без змін | порожньо |

Тексти помилок для користувача:

| Помилка | Текст |
| --- | --- |
| `HttpError` зі статусом 404 | `Не знайдено (HTTP 404).` |
| `HttpError` 429 | `Забагато запитів (HTTP 429). Спробуйте за кілька секунд.` |
| `HttpError` 500–599 | `Сервер TVmaze недоступний (HTTP 503). Спробуйте пізніше.` — зі справжнім статусом |
| будь-який інший `HttpError` | `Помилка запиту (HTTP 400).` — зі справжнім статусом |
| `TypeError` — так `fetch` повідомляє про збій мережі | `Мережа недоступна. Перевірте підключення.` |
| будь-що інше | `Щось пішло не так. Спробуйте ще раз.` |

Тести порівнюють тексти точно, лише «...» зараховують як «…».

## 4. Завдання

Виконуйте завдання по черзі: кожне спирається на попередні. T1–T3 пишете
власноруч, AI-агент може лише пояснювати. T4 спершу пише AI-агент, а ви
перевіряєте чернетку й виправляєте її (лабораторна робота, §5.2).

Правила пронумеровано: T2.4 — четверте правило завдання T2. Кожне правило
перевіряє `npm run check`:

- **тест**, назва якого починається з номера правила;
- або **перевірка типів** у `check/types.check.ts`: помилка компілятора
  вказує на рядок, а номер правила стоїть у коментарі над ним або в кінці
  рядка. «Unused '@ts-expect-error' directive» означає, що ваш тип пропускає
  значення, яке мав би заборонити.

### T1. Типи відповідей API

**Що має вийти.** У `src/types.ts` — експортовані інтерфейси `Show` і
`SearchResult`, що точно описують відповіді TVmaze (§3.1–3.2): `null` там, де
він буває, і ніде більше.

**Як.** Відкрийте `https://api.tvmaze.com/search/shows?q=girls` у браузері
(експеримент Е1) і `check/fixtures/search.json`. Серіали, у яких поля
бувають `null`, є, наприклад, у пошуку `kitchen`.

**Правила:**

1. `id` — `number`; `name` і `url` — `string`; `genres` — масив рядків.
2. `image`, `summary`, `premiered` і `rating.average` можуть бути `null`, а
   `name` — ні. `image`, коли не `null`, — об'єкт з рядками `medium` і
   `original`; `rating` — завжди об'єкт.
3. `SearchResult` — `{ score: number; show: Show }`.
4. Записані відповіді TVmaze з `check/fixtures/` підходять під ваші типи без
   змін.

**Перевірка:** `npm run typecheck`, блок T1 у `check/types.check.ts`. Після
T1 зникають і помилки в `src/view.ts`.

### T2. Запити

**Що має вийти.** У `src/api.ts` — типізовані функції запитів до TVmaze. Дані
з мережі мають тип `unknown`: код вважає їх серіалами лише після перевірки
type guard.

**Правила:**

1. `class HttpError extends Error` з полем `readonly status: number`:
   `new HttpError(404)` — помилка зі `status` 404 і статусом у повідомленні.
2. `getJson(url: string): Promise<unknown>` надсилає GET-запит через `fetch`.
   Якщо статус поза 200–299 — відхиляє проміс з `HttpError`, інакше повертає
   розібране тіло JSON. Помилку самого `fetch` (збій мережі) не змінює.
3. `isShow(value: unknown): value is Show` повертає `true`, якщо `value` —
   об'єкт з числовим `id`, рядковим `name` і масивом `genres`, інакше
   `false`. `isSearchResult(value: unknown): value is SearchResult` — так само
   для об'єкта з числовим `score` і полем `show`, на якому `isShow` дає
   `true`.
4. `searchShows(query: string): Promise<Show[]>` запитує
   `GET https://api.tvmaze.com/search/shows?q=<запит>` з закодованим запитом:
   «law & order» доходить до API повністю. Повертає серіали, а не елементи
   `{ score, show }`, у порядку відповіді; немає збігів — `[]`.
5. `getShow(id: number): Promise<Show>` запитує
   `GET https://api.tvmaze.com/shows/<id>` і повертає серіал.
6. На статус 404, 429, 500 чи 503 обидві функції відхиляють проміс з
   `HttpError` цього статусу.
7. Якщо тіло відповіді не тієї форми (`isSearchResult` чи `isShow` дає
   `false`), обидві функції відхиляють проміс з
   `new Error('Неочікувана відповідь API')`.

**Перевірка:** тести T2 (`check/2-api.test.js`) і блок T2 у
`check/types.check.ts`.

### T3. Стани й тексти

**Що має вийти.** У `src/state.ts` — тип стану сторінки й дві функції, що
перетворюють стан і помилку на текст для користувача (§3.4).

**Правила:**

1. `export type ViewState` — об'єднання шести станів з §3.4, кожен лише зі
   своїми полями. Поле `status` розрізняє стани.
2. `errorMessage(err: unknown): string` повертає текст помилки з §3.4.
   `HttpError` розпізнає лише через `instanceof`: звичайний об'єкт
   `{ status: 404 }` — це «будь-що інше».
3. `messageFor(state: ViewState): string` повертає текст рядка статусу з
   §3.4. Усередині — `switch (state.status)` з гілкою `default`, у якій стан
   присвоєно змінній типу `never`: якщо колись додати сьомий стан і не
   обробити його, компілятор покаже помилку. Під час виконання ця гілка не
   настає, тож у ній можна просто кинути помилку.

**Перевірка:** тести T3 (`check/3-state.test.js`) і блок T3 у
`check/types.check.ts`.

### T4. Застосунок: AI-чернетка → перевірка → виправлення

**Що має вийти.** Пошук і сторінка серіалу працюють у браузері зі справжнім
TVmaze. Після «Знайти» рядок статусу показує «Завантаження…», а потім картки,
«Нічого не знайдено…» або текст помилки. Клік по картці відкриває серіал.

**Запит для AI-агента** (вставте слово в слово):

> Напиши src/app.ts застосунку ShowFinder на TypeScript. Експортуй три
> функції: loadSearch(query, setState) і loadShow(id, setState) повідомляють
> про кожну зміну стану сторінки через setState, а start() підключає форму
> пошуку й картки серіалів до сторінки. Використай типи з src/types.ts і
> src/state.ts, функції з src/api.ts і src/state.ts, показ — з src/view.ts,
> елементи сторінки — з src/dom.ts. Теку check/ не відкривай і не змінюй;
> інші файли src/ і tsconfig.json не змінюй.

**Правила:**

1. `loadSearch(query: string, setState: (state: ViewState) => void):
   Promise<void>` шукає за запитом без пробілів на краях. Порожній запит —
   лише `setState({ status: 'idle' })`, без запиту до API.
2. Інакше — спершу стан `loading`, ще до запиту, потім один стан: `results`
   з `query` і серіалами або `empty` з `query`, якщо нічого не знайдено.
3. Будь-яка помилка — стан `error` з `message: errorMessage(err)`. Проміс
   `loadSearch` ніколи не відхиляється: у Console немає
   `Uncaught (in promise)`.
4. `loadShow(id: number, setState: (state: ViewState) => void):
   Promise<void>` — стан `loading`, потім `show` або `error`, як у правилі 3.
5. `start(): void` бере елементи сторінки через `pageElements()` лише
   всередині себе: тести виконуються в Node, де сторінки немає. Надсилання
   форми без перезавантаження сторінки викликає `loadSearch` зі значенням
   поля. Клік по картці `button[data-id]` викликає `loadShow` з її id
   (делегування подій на `#content`, як у ЛР-9). Кожен стан показується за
   §3.4: текст `messageFor(state)` — у `#status` через `renderStatus`, у
   `#content` — картки, сторінка серіалу або порожньо. Після запуску —
   стан `idle`.

**Перевірка:** тести T4 (`check/4-app.test.js`) і блок T4 у
`check/types.check.ts` перевіряють правила 1–4. Якщо всі тести T4 падають з
`ReferenceError: document is not defined`, порушено правило 5. Решту правила
5 перевіряєте в браузері й чек-листом Network (§6).

## 5. Обмеження

- Змінюйте лише `src/types.ts`, `src/api.ts`, `src/state.ts` і `src/app.ts`.
  Решта файлів лишається такою, як у starter-проєкті.
- У `src/` немає `any` і коментарів `@ts-ignore`, `@ts-nocheck`,
  `@ts-expect-error` (їх шукають тести «§5»): помилку типів виправляють у типі
  чи коді, а не вимикають.
- Типи імпортують через `import type`.
- Лише `fetch` і лише `https://api.tvmaze.com`: без бібліотек і фреймворків.
- Без `alert()`, `confirm()` і `prompt()`.
- T1–T3 і виправлення T4 пишете ви. AI-агент пише лише чернетку T4 і може
  пояснювати (лабораторна робота, §5.2).

## 6. Чек-лист Network

`npm run check` не бачить ні справжнього TVmaze, ні браузера: їх перевіряєте
ви. Поки працює `npm run watch`, відкрийте `index.html` через Live Preview у
Chrome або Edge, а в DevTools → Network увімкніть **Preserve log** і фільтр
**Fetch/XHR**. Пройдіть чек-лист на фінальній версії й додайте до звіту знімок
екрана для кожного пункту.

1. **N1 · Пошук.** Знайдіть «law & order». У Network — запит до
   `/search/shows` зі статусом 200, у Payload — `q: law & order`. На сторінці —
   картки й «Знайдено серіалів: N».
2. **N2 · Повільна мережа.** Throttling — **Slow 4G**. Після «Знайти» рядок
   статусу показує «Завантаження…», доки не прийде відповідь.
3. **N3 · Немає мережі.** Throttling — **Offline**. Пошук показує «Мережа
   недоступна. Перевірте підключення.», у Console немає `Uncaught`. Поверніть
   **No throttling**: наступний пошук знаходить серіали.
4. **N4 · Сторінка серіалу.** Клік по картці: у Network — запит
   `/shows/<id>` зі статусом 200, на сторінці — серіал, у статусі —
   «Серіал: <назва>».
