## 1. Загальна ідея

**ShowFinder** — пошук серіалів у [TVmaze](https://www.tvmaze.com) через його
публічний [API](https://www.tvmaze.com/api). Користувач вводить назву, бачить
знайдені серіали, вибирає один і отримує його сторінку: дані, опис, епізоди за
сезонами й акторів. Стан живе лише в пам'яті: після перезавантаження сторінки
застосунок починає спочатку.

HTML, CSS, шаблони станів і модуль показу даних уже готові. Ваша частина —
запити до API й поведінка застосунку: коли запитувати, що показувати, поки
відповідь іде, і як реагувати на кожну відповідь і кожен збій.

> Перевірка — це ця специфікація у вигляді коду: назва кожного рядка
> `check.html` — правило з §4. Якщо перевірка й текст нижче здаються вам
> суперечливими, повідомте викладача.

## 2. Структура проєкту

**Завантажити:** [showfinder-starter.zip](/labs/showfinder-starter.zip)
(≈ 60 КБ). Розпакуйте архів в окремий репозиторій або в теку `lab-11/`
спільного репозиторію з лабораторними.

│   ├── view.js         показ даних TVmaze — наданий, не змінюється
│   ├── main.js         точка входу

│   └── app.js          пошук, сторінка серіалу, стани

├── experiments.html    сторінка для експериментів §4 лабораторної

Відкривайте `index.html` і `check.html` через Live Preview або

## 3. Сторінка, API і стани

### 3.1. Статична розмітка

Ідентифікатори й атрибути нижче — контракт: самоперевірка шукає саме їх.
Розмітку можна доповнювати, але не перейменовувати.

| Елемент | Що це |
| --- | --- |
| `form#search` | поле `name="query"` (`#search-query`) і кнопка «Знайти» |
| `#status` | рядок статусу пошуку, `role="status"`, є в HTML від початку; змінюється лише його текст |
| `#results` | область результатів: картки, стан завантаження, повідомлення або помилка |
| `#details` | область сторінки серіалу; на старті — «Виберіть серіал у результатах пошуку.» |
| `template#state-loading` | «Завантаження…» зі спінером |
| `template#state-message` | повідомлення: порожній результат, «Серіал не знайдено» |
| `template#state-error` | помилка: текст у `.state__text` і кнопка `[data-action="retry"]` «Спробувати ще» |

### 3.2. TVmaze API

| Що | Запит | Відповідь |
| --- | --- | --- |
| Пошук | `GET https://api.tvmaze.com/search/shows?q=<запит>` | масив до 10 елементів `{ score, show }`; немає збігів — `200 []` |
| Серіал | `GET https://api.tvmaze.com/shows/<id>` | об'єкт серіалу; немає такого id — `404` |
| Епізоди й актори | `GET /shows/<id>/episodes` і `GET /shows/<id>/cast` або `embed` у запиті серіалу | масиви |

Решта — у [документації TVmaze](https://www.tvmaze.com/api) і вашому `API.md`.
TVmaze гарантує щонайменше 20 запитів за 10 секунд з однієї IP-адреси, а на
`429` радить почекати кілька секунд.

### 3.3. Показ даних: `src/view.js`

| Експорт | Що робить |
| --- | --- |
| `renderResults(container, shows)` | показує масив серіалів картками в тому самому порядку: `<li data-id>` з кнопкою `[data-action="open"]`; порожній масив — порожній список |
| `renderShow(container, { show, episodes, cast })` | показує сторінку серіалу із заголовком `#show-title`, епізодами за сезонами й акторами |

Обидві функції приймають об'єкти у формі відповідей TVmaze: серіал (`show`),
а не елемент відповіді пошуку `{ score, show }`. Вони перевіряють аргументи й
кидають `TypeError` з поясненням, якщо форма даних не та. Повідомлення про
стани (§3.4) показуєте ви.

### 3.4. Стани й тексти

`<запит>` — значення поля без пробілів на краях.

| Стан | Де | Що бачить користувач |
| --- | --- | --- |
| Завантаження | `#results` або `#details` | «Завантаження…» (шаблон `#state-loading`), в області — `aria-busy="true"`; для пошуку статус «Завантаження…» |
| Результати | `#results` | картки `renderResults`, статус «Знайдено: N» |
| Нічого не знайдено | `#results` | «Нічого не знайдено за запитом «<запит>»», статус — той самий текст |
| Серіал не знайдено | `#details` | «Серіал не знайдено» |
| Немає мережі | область запиту | «Немає з'єднання з TVmaze.» і «Спробувати ще» |
| Збій TVmaze | область запиту | «Не вдалося отримати дані від TVmaze.» і «Спробувати ще» |
| Забагато запитів | область запиту | поки застосунок чекає — стан завантаження, а статус пошуку «Забагато запитів до TVmaze, повторюю…»; після другої відмови — «Забагато запитів до TVmaze.» і «Спробувати ще» |

Для помилок пошуку статус показує той самий текст, що й `#results`.

## 4. Завдання

Три challenges виконуйте по черзі: кожен спирається на попередні. Кожен
challenge — той самий цикл (лабораторна робота, §5.2): AI-агент пише чернетку
за запитом нижче, ви комітите її без змін, перевіряєте за правилами й
виправляєте власноруч. Між Challenge 2 і Challenge 3 — файл правил для агента.

Правила пронумеровано: C3.2 — друге правило Challenge 3. Під тим самим номером
його перевіряє `check.html`.

### C1. Пошук

**Що має вийти.** Користувач вводить назву, і застосунок шукає серіали в
TVmaze, коли користувач перестає вводити, або одразу після Enter. Поки запит
триває, область результатів показує «Завантаження…». Потім — список серіалів
і рядок статусу «Знайдено: N», а якщо нічого не знайдено — повідомлення про
це.

**Код:** `searchShows()` у `src/api.js`, пошук і його стани в `src/app.js`.
Розмітка, шаблони станів і `renderResults` уже є (§3).

**Запит для AI-агента:**

> Зроби пошук серіалів через TVmaze API (https://www.tvmaze.com/api): поле
> в формі #search, результати в #results через renderResults з src/view.js.

**Правила:**

1. Запит пошуку — `GET https://api.tvmaze.com/search/shows?q=<запит>` через
   `fetch`. Запит без пробілів на краях і закодований: «Law & Order» доходить
   до API повністю.
2. Результати показує `renderResults` у порядку відповіді API; статус —
   «Знайдено: N».
3. Пошук запускає введення в полі (подія `input`). Серія введень дає один
   запит, не пізніше ніж за 500 мс після останнього введення.
4. Enter шукає одразу, без перезавантаження сторінки й без другого запиту того
   самого пошуку.
5. Якщо в полі менше 2 символів, запиту немає, а `#results` і статус порожні.
   Пошук, що ще не завершився, після цього вже не показується.
6. Поки запит триває, `#results` має `aria-busy="true"` і показує
   «Завантаження…», статус — «Завантаження…». Після відповіді
   `aria-busy="true"` немає.
7. Порожня відповідь (`200 []`) — не помилка: «Нічого не знайдено за запитом
   «<запит>»» у `#results` і в статусі, без «Спробувати ще».
8. Відповідь на старіший запит ніколи не замінює новішу, в якому б порядку
   вони не прийшли. Поки новіший запит триває, `#results` показує
   «Завантаження…».
9. Жоден запит не потребує preflight: лише `GET`, без власних заголовків і
   без `Content-Type`; без `mode: 'no-cors'` і `credentials: 'include'`.

**Перевірка:** блок «C1 · Пошук» у `check.html`. Знадобляться експерименти 1,
6, 10 і 12 лабораторної.

### C2. Сторінка серіалу

**Що має вийти.** Клік по картці показує праворуч (на вузькому екрані —
нижче) сторінку серіалу: дані, опис, епізоди за сезонами й акторів. Поки
сторінка завантажується, вона показує «Завантаження…», а список результатів
лишається на місці. Уже відкритий раніше серіал з'являється одразу.

**Код:** `getShow()` у `src/api.js`, вибір серіалу і його стани в
`src/app.js`. Що саме запитувати, щоб отримати епізоди й акторів, — у
документації TVmaze (§3.2) і вашому `API.md`.

**Запит для AI-агента:**

> Коли користувач вибирає серіал у списку, покажи в #details його опис,
> епізоди й акторів через renderShow з src/view.js.

**Правила:**

1. Клік по картці показує в `#details` через `renderShow` сторінку цього
   серіалу: назву, епізоди за сезонами й акторів.
2. Усі дані сторінки запитано одразу: один запит з `embed` або кілька
   паралельних — не один за одним. Лише ендпоїнти з документації TVmaze, без
   запитів по одному епізоду чи актору.
3. Поки сторінка завантажується, `#details` має `aria-busy="true"` і показує
   «Завантаження…». Список результатів лишається на місці, і його кнопки
   працюють.
4. Серіал, уже завантажений раніше, відкривається без нового запиту.
5. Якщо вибрати інший серіал, поки попередній ще завантажується, показується
   лише останній вибраний. Поки він завантажується, `#details` показує
   «Завантаження…».

**Перевірка:** блоки «C2 · Сторінка серіалу» і C1 у `check.html`.
Знадобляться експерименти 3, 5, 6 і 8 лабораторної.

### C3. Помилки

**Що має вийти.** Кожен збій пояснено користувачеві в тій області, де він
стався, текстом із §3.4, а поруч — «Спробувати ще». На 429 застосунок сам
чекає кілька секунд і повторює запит один раз, як радить документація TVmaze.
Інші збої сам не повторює: це робить користувач кнопкою «Спробувати ще».

**Код:** `src/api.js` і `src/app.js`; шаблон `#state-error` з кнопкою
«Спробувати ще» вже є.

**Запит для AI-агента** (з вашим `AGENTS.md` у проєкті):

> Додай обробку помилок і повторну спробу для всіх запитів.

**Правила:**

1. HTTP-помилка — не дані: відповідь 4xx чи 5xx ніколи не показується як
   результати чи «Нічого не знайдено».
2. `404` для серіалу — «Серіал не знайдено» в `#details`.
3. Відповідь `5xx` і відповідь, що не є JSON, — «Не вдалося отримати дані від
   TVmaze.» і «Спробувати ще» в області запиту; для пошуку — і в статусі.
4. Збій мережі (проміс `fetch` відхилено) — «Немає з'єднання з TVmaze.» і
   «Спробувати ще»; для пошуку — і в статусі.
5. «Спробувати ще» повторює той самий запит; успішна відповідь замінює
   помилку.
6. `429`: застосунок сам повторює запит один раз, через 2–5 с. Поки він чекає,
   область у стані завантаження, а статус пошуку — «Забагато запитів до
   TVmaze, повторюю…». Другий `429` поспіль — «Забагато запитів до TVmaze.» і
   «Спробувати ще», без нових автоматичних запитів. Інші збої застосунок сам не
   повторює.
7. Після будь-якого збою завантаження завершено: `aria-busy="true"` немає,
   «Завантаження…» не видно.
8. Невдалі відповіді не кешуються: повторне відкриття серіалу після помилки
   надсилає новий запит.
9. Скасований запит — не помилка. У Console застосунку немає `Uncaught` і
   `Uncaught (in promise)` за жодного сценарію.
10. Користувач бачить лише тексти з §3.4: без `TypeError`, `Failed to fetch`,
    кодів статусу, JSON і `alert()`. Технічні подробиці — у Console
    (`console.error`).

**Перевірка:** блоки «C3 · Помилки», C1 і C2 у `check.html`. Відтворіть збої
й у справжньому застосунку: Offline і Request blocking у Network. Знадобляться
експерименти 1, 2, 4, 6 і 7 лабораторної.

## 5. Обмеження

- Змінюйте `index.html`, `styles.css` і `src/`, крім `src/view.js`.
  `check.html`, `check/`, `offline.html` і `src/view.js` залишаються такими,
  як у starter-проєкті.
- Лише Fetch API і лише `https://api.tvmaze.com`: без бібліотек, фреймворків і
  CORS-проксі.
- Дані потрапляють на сторінку лише через `renderResults` і `renderShow`.
- Без `alert()`, `confirm()` і `prompt()`.
- Код виправлень пишете ви. AI-агент пише лише чернетку за запитом challenge
  (§4) і може пояснювати (§5.2 лабораторної роботи).

## 6. Чек-лист Network

`check.html` відповідає на запити сама, тож справжній TVmaze перевіряєте ви: у
`index.html`, у Chrome або Edge, з **Preserve log** і фільтром **Fetch/XHR** у
панелі Network. Пройдіть чек-лист на фінальній версії й додайте до звіту знімок
екрана для кожного пункту.

1. **N1 · Запит пошуку.** Знайдіть «girls». У запиті — статус 200, параметр `q`
   у Payload, масив у Preview; у Response Headers — `cache-control` і
   `access-control-allow-origin`.
2. **N2 · Повільна мережа.** Throttling — Slow 4G. Видно «Завантаження…».
   Введіть «gir», дочекайтеся запиту в Network і допишіть «ls»: попередній
   запит отримує статус `(canceled)`, а на сторінці — результати «girls».
3. **N3 · Немає мережі.** Request blocking для `api.tvmaze.com` (або
   throttling Offline): пошук показує «Немає з'єднання з TVmaze.». Після
   зняття блокування «Спробувати ще» знаходить серіали.
4. **N4 · Initiator.** Для запиту сторінки серіалу вкладка Initiator показує
   рядок вашого коду, що надіслав запит.
5. **N5 · Кеш.** Відкрийте серіал, потім інший і знову перший: утретє запиту
   немає (C2.4). Повторіть той самий пошук: що показує колонка Size і чому
   (розділ Caching документації TVmaze, експеримент 8 лабораторної)?
6. **N6 · Console.** Увесь сценарій — пошук, сторінка серіалу, збої з N3 —
   без `Uncaught` у Console. Червоні рядки «Failed to load resource» від
   заблокованих запитів пише браузер, а не ваш код.
